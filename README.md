# herdr-router

Route a coding task to the right agent, model, and effort, then launch it in [Herdr](https://herdr.dev).

```
 difficulty                                    (one line per model, low → max)
     ▲
   4 │                         ●──●──● opus
   3 │            ●──●──●──●──● sol
   2 │       ●   (glm / mimo)
   1 │  ●──●──●──●──● haiku
   0 │  ●──●──●──●──● luna
     └──────────────────────────────────────▶ duration
          0      1        2          3
```

A task is assessed along any number of **dimensions** (difficulty, duration, scope, task type, …). Each **profile** (an agent + model + effort) sits at a **point** on the dimensions it cares about. A task goes to the profile it is closest to, where being above a profile (too hard for it) counts three times as much as being below it. The profile with the lowest penalty wins. Dimensions and profiles are data, so you can add a dimension or move a profile without touching code. The web editor draws the result as a territory map: the plane is tinted by the profile a task landing there would go to, and you drag the points anywhere to reshape it.

The default is generated by `tools/build_default_policy.py` from [Artificial Analysis](https://artificialanalysis.ai/) data (fetched 2026-10-11) and leans toward value. Every model with effort control gets one profile per effort (low … max), drawn as a line on the chart like AA's per-model curves. Difficulty follows the Intelligence Index (`(II − 30) / 7`), duration follows the effort level, `cost` is AA's USD per task and `time` is AA's time per task in minutes (the "Intelligence Index vs. Time per Task" chart, scaled to each effort by AA's end-to-end response times). `cost_weight` (0.6 per dollar, times a per-agent factor: OpenCode 0.25 because OpenCode Go is a flat subscription) and `time_weight` (0.01 per minute, a tie-breaker) turn both into penalty. All five efforts are drawn, but only the common ones route by default (Luna low/high, Haiku medium/high, Sonnet medium, Sol medium/high/xhigh, Opus medium/high/xhigh); enable the others in the editor. Every profile carries a `note` with the numbers it came from. Trivial and small edits go to cheap open models (DeepSeek V4.1 Flash, GLM-5.3 Flash) and Luna / Haiku, GPT-6.1 Sol medium / high / xhigh takes most real work (about half the plane), and Opus high / xhigh takes expert-level design. Specialists take their own task type (Codex for review, Sonnet for research, Cursor for UI).

**Same model, different agent.** The policy's `models` catalog lists each model's id in every agent that can run it (for example GLM-5.3 is `opencode-go/glm-5.3` in OpenCode and `glm-5.3` in Droid). In the editor, a selected dot shows an agent switcher; switching rewrites the profile's `kind` and `model` from the catalog. Colours follow the model vendor, not the agent.

## How a decision is made

1. **Inline overrides** are read and removed from the prompt:
   - `@opus`, `@codex`, `@haiku`, … are aliases that pin a profile. `@<profile-id>` also works.
   - `!hard`, `!long`, `!quick`, … pin a dimension. `!<dimension>=<value>` also works.
2. **Assessment**: every dimension becomes one question in a single System One call. By default this goes to [Jev](https://opencode.ai/docs/zen/) on OpenCode Zen (`jev-1.13-free`, no key needed). The answer is a probability distribution per dimension. When the call fails, keyword heuristics (Chinese and English) fill in difficulty, duration, and task type as point estimates. If their confidence is low, difficulty is bumped up one step.
3. **Scoring** (lower is better):
   - score dimension: `weight × E[under_penalty × max(0, task − point − tolerance) + over_penalty × max(0, point − task − tolerance)]`, in levels. `tolerance` (0.5) is the free zone around a point. A dimension left out of a profile's point costs nothing.
   - choice dimension: `weight × Σ P(option) × (1 − affinity)`. When nothing is known about a choice dimension, a uniform prior is used.
   - plus `cost_weight × cost × agent_cost[kind]` (USD per task) and `time_weight × time` (minutes per task)

   `under_penalty` (3) is larger than `over_penalty` (1) on purpose: an underpowered agent costs more than an overpowered one. A profile whose CLI is not on PATH is skipped. Ties go to the cheaper profile. Policies from version 2 (ranges) are migrated on load: each range becomes its midpoint, and a full range becomes "does not care".

`herdr-router route "<task>"` prints the per-dimension distributions, the winner, and the top 3 profiles with their penalty breakdown. `--json` prints the full ranking.

## Install

```bash
ln -s ~/Projects/herdr-router/bin/herdr-router ~/.local/bin/herdr-router   # CLI
herdr plugin link ~/Projects/herdr-router                                  # Herdr plugin
ln -s ~/Projects/herdr-router/skill ~/.claude/skills/herdr-route           # Claude Code skill
```

Python ≥ 3.11, standard library only.

## Use

```bash
herdr-router route "修复登录偶现的崩溃"            # explain the decision, launch nothing
herdr-router dispatch "修复登录偶现的崩溃"         # split a pane, start the agent, send the task
herdr-router dispatch "@codex 把所有 Debug.Log 换成 Logger.Info" --json
herdr-router route "…" --profile opus-high          # pin a profile
herdr-router route "…" --kind codex --effort high   # best codex profile, effort patched
herdr-router classify "设计状态同步架构"            # raw per-dimension distributions
```

Every dispatch is appended to `~/.local/state/herdr/plugins/herdr-router/decisions.jsonl`. The editor plots these entries on the chart.

## Web editor

```bash
herdr-router ui            # http://127.0.0.1:8765/?token=…
herdr-router ui --lan      # also listen on LAN / Tailscale addresses (prints each URL)
herdr-router ui --stop     # stop a background editor started by the plugin action
```

- **路由图** (routing map): a dark scatter chart over any two score dimensions. Each profile is a labelled dot at its point, coloured by agent vendor, and can be dragged **anywhere** (snaps to 0.05). Hollow dots are specialists (for example "仅 review"), dashed ones are not installed; a profile that ignores one axis is a dashed line along it, and one that ignores both is listed under the chart. The background is the **territory map**: the plane is tinted by the profile that would win a task there, with thin borders where the winner changes. It is computed server-side by `score.territory` (so it always matches real routing), coarse while you drag and fine once you drop. Hover anywhere to see the winner and runner-ups with their penalties. The type selector shows territories for one task type. The command bar on top runs a trial: the task's position is marked, the winner pulses, and the top five penalties plus the launch command appear below the chart. The side panel lists profiles grouped by agent with the share of the map each one wins (0% means it is completely shadowed). Selecting one edits it: model (dropdown from each CLI's model list: Claude aliases, `~/.codex/models_cache.json`, `cursor-agent --list-models`), effort limited to what that model supports, a slider per dimension with a "不挑" (does not care) switch, type affinity, and prompt prefix.
- **维度** (dimensions): add, remove, reorder, or rename dimensions, and edit their question, levels or options, and weight. When a dimension loses levels, points above the new top level move down to it.
- **试运行** (trial run): accepts multiline task descriptions (⌘/Ctrl+Enter to run) and examples. The recommendation shows model, agent, effort, actual penalty breakdown and the difference from the runner-up. Expand diagnostics for dimension distributions and the full ranking, or copy the shell-quoted startup command. Trials use a snapshot of the unsaved draft; changing the task, assessment mode or policy marks the previous result as stale.
- **设置 / JSON** (settings / JSON): penalty knobs, backend, aliases, and raw JSON for the rest.

The profile list supports text search and status filters (enabled, disabled, missing CLI, or zero coverage in the current map slice). History, disabled profiles and labels have separate display controls; hiding a profile on the chart does not disable routing. Coverage describes only the selected two-dimensional slice, not real task frequency or overall usefulness. The profile editor groups basic information, coordinates, task affinity and advanced parameters, with numeric coordinate inputs alongside sliders.

Undo/redo retains the last 100 draft operations; a continuous field edit or chart drag is one operation. Use the buttons or ⌘/Ctrl+Z and ⌘/Ctrl+Shift+Z in policy fields (task and JSON text editors keep native text undo). **放弃修改** restores the last acknowledged saved policy and can itself be undone. Saving acknowledges the submitted snapshot: edits made while the request is in flight remain unsaved. A draft summary lists the changed profiles and policy sections.

Saving validates the policy on the server, keeps the last 10 versions in `policy.backups/`, and writes `~/.config/herdr/plugins/config/herdr-router/policy.json`. The file is replaced atomically. The CLI reads the policy on every run, so changes apply immediately.

Security: every API call needs the token. It is stored in the state dir; the first visit trades the `?token=` link for an HttpOnly cookie. Requests whose `Host` header is an unknown domain are refused, which defends against DNS rebinding. The editor can change launch arguments but **cannot dispatch agents**.

Plugin actions:
- `herdr-router.route` opens a popup. Type a task, review the ranking, then press Enter to dispatch; the popup closes by itself about a second after a successful dispatch (a failure stays on screen until you press Enter). Use `k`/`m`/`e` to change the profile, model, or effort.
- `herdr-router.route-selection` does the same with the terminal selection as the task.
- `herdr-router.open-editor` starts the editor in the background if needed and opens it in the browser.

Keybinding example (`~/.config/herdr/config.toml`, then `herdr server reload-config`):

```toml
[[keys.command]]
key = "cmd+shift+r"
type = "plugin_action"
command = "herdr-router.route"
```

## Policy file

The default is `config/policy.default.json`. A user `policy.json` replaces it wholesale.

```jsonc
{
  "dimensions": [
    { "id": "difficulty", "type": "score", "weight": 1, "instructions": "How hard…", "levels": ["Trivial…", "…"] },
    { "id": "task_type",  "type": "choice", "weight": 6, "instructions": "What kind…", "options": { "review": "…" } }
  ],
  "profiles": [
    { "id": "codex-review", "kind": "codex", "model": "gpt-6.1-sol", "effort": "high", "cost": 3,
      "affinity": { "task_type": { "*": 0, "review": 1 } } },    // no point: any difficulty / duration
    { "id": "codex-sol-high", "kind": "codex", "model": "gpt-6.1-sol", "effort": "high", "cost": 3,
      "point": { "difficulty": 2.8, "duration": 1.6 } }          // left-out dimension = does not care
  ],
  "scoring": { "under_penalty": 4, "over_penalty": 0.5, "tolerance": 0.5, "cost_weight": 0.6,
               "agent_cost": { "opencode": 0.25 }, "time_weight": 0.01 },
  "aliases": { "@review": "codex-review", "!hard": { "difficulty": 3 } }
}
```

Backends that speak the same System One API:
- Paid `jev-1.13`: set `backend.model = "jev-1.13"` and export `OPENCODE_API_KEY`.
- Local [Kev](https://github.com/jaredpalmer/kev): set `backend.base_url = "http://127.0.0.1:8009"` and `model = "kev-latest"`.

Agent flags (checked against each CLI's `--help`):

| kind | model | effort |
|---|---|---|
| claude | `--model` | `--effort low…max` |
| codex | `-m` | `-c model_reasoning_effort=…` (passed as-is; gpt-6.x supports up to max) |
| kimi | `-m` | `--thinking` / `--no-thinking` (low) |
| cursor | `--model name[effort=…]` | in the model bracket |
| opencode | `mini -m provider/model` (the full TUI has no model flag; `mini` does, and Herdr detects it) | none |
| droid | `--settings <state>/droid/<model>-<effort>.json`, written right before launch | `reasoningEffort` in that file |
